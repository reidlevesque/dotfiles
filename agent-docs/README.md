# Agent Docs

Slash commands and shared documentation for AI coding assistants.

## Installation

```bash
./install.sh
```

This installs:

- Slash commands to `~/.claude/commands/`
- Output style symlinks to `~/.claude/output-styles/`
- Agent instructions symlink to `~/.config/AGENTS.md`
- Codex instructions symlink to `~/.codex/AGENTS.md`
- Claude Code instructions symlink to `~/.claude/CLAUDE.md` (Claude reads only this
  path for user-level instructions; it ignores `~/.config/AGENTS.md`)
- Common Codex configuration symlink to `/etc/codex/config.toml` (requires `sudo`)
- Machine-specific Codex configuration remains unmanaged at `~/.codex/config.toml`
- External skills from source clones to `~/.codex/skills/` and `~/.claude/skills/`
- Legacy `~/.config/AGENT.md` removal when that file is a symlink or generated by this repo
- Portable Claude settings merged into the local `~/.claude/settings.json`
- Portable Droid settings merged into the local `~/.factory/settings.json`
- Settings symlink to `~/.config/amp/settings.json`

## External Skills

External skills are listed in `install.sh` and are expected to be cloned under
`~/dev`. The installer warns when a clone is missing; it does not clone missing
repositories. When a clone exists, it runs `git up`, links the skill into Codex
and Claude, and runs any declared install command from the clone root. Skill
collections link each child directory with a `SKILL.md` unless its name appears
in `DISABLED_EXTERNAL_SKILLS`. The installer also removes symlinks for disabled
skills from its managed skill directories.

## Usage

Type `/` in Claude Code to see available commands.

## Structure

- `commands/` - Slash commands
- `docs/` - Reference documentation
- `output-styles/` - Claude Code output styles, selected via `outputStyle` in `settings/claude.json`
- `settings/` - Configuration files
- `AGENTS.md` - Shared agent instructions

## Claude Settings

`settings/claude.json` contains portable defaults that should remain consistent
across machines. The installer merges these defaults into a normal local
`~/.claude/settings.json`, with the tracked values taking precedence.

Claude Code can update the local file without changing this repository. Keep
machine-specific values, interactive preferences, and runtime state only in the
local file.

## Droid Settings

`settings/droid.json` contains portable defaults, not Droid's writable settings
file. The installer merges these defaults into a normal local
`~/.factory/settings.json`, with tracked values taking precedence. Other local
settings, trusted folders, timestamps, and banner state stay on the machine and
must not be added to the template.

When migrating the old settings symlink, the installer first saves its contents
to a private `~/.factory/settings.json.backup.*` file. It then replaces the symlink
with a regular file without changing the tracked template. Invalid JSON stops
installation without replacing the existing settings.
